**Laylaミニアプリは、Layla内で動作する自己完結型のWebアプリです。ブリッジを介して、スマートフォンにすでにあるAI（ローカルモデル、画像生成、音声、キャラクター、プライベートファイルストレージ）をAPIキーやサーバーなしで呼び出せます。**

![暗い背景にコード記号が描かれたネオン調のサイバーキャットロゴ。](./codekitty-logo.avif)

[CodeKitty](https://apps.layla-cloud.com/app/codekitty)は、ほかのミニアプリを作るためのミニアプリです。コードエディター、ライブプレビュー、プロジェクトライブラリ、画像ジェネレーター、AIコーディングアシスタントを1つのHTMLファイルにまとめています。ミニアプリシステムのほぼすべての部分に触れているため、この記事ではCodeKittyを例に、その仕組みを説明します。

## Laylaミニアプリとは？

ミニアプリは、LaylaがWebView内で実行する一般的なWebアプリケーション（HTML、CSS、JavaScript）です。単なるWebページ以上のものにしているのが、ホストブリッジです。

通常、LLMを使うWebアプリにはAPIキー、サーバー、ネットワーク接続が必要で、データを外部へ送信します。Laylaミニアプリは違います。Layla内で動作し、ローカルモデル推論、画像生成、テキスト読み上げ、キャラクター一覧、アプリごとのプライベートファイルシステムなど、端末にすでにインストールされている機能をLaylaから利用します。

これは通常の構成を逆転させます。AIはアプリが外部に呼び出すサービスではなく、ホストが提供する機能です。認証先となる外部サービスがないため、入力するキーも、設定するendpointも、作成するアカウントもありません。推論は、読み込んだ[GGUFモデル](/ja/what-are-gguf-models-what-are-model-quants/)を使用して端末のハードウェア上で実行されます。

ミニアプリはZIPとして配布され、ルートにはメタデータ用の`app.json`、アプリ本体の`index.html`、および各種アセットが置かれます。

## CodeKittyとは

CodeKittyはスマートフォン上で動作し、インストール可能なLaylaミニアプリを作成するIDEです。

プロジェクトを、ファイル名をキーとするJavaScriptオブジェクト、つまり仮想ファイルシステムとして扱います。新しいプロジェクトは`index.html`、`app.json`、`icon.jpg`、`bg.jpg`の4項目から始まります。これらのファイルはディスクではなくメモリ内にあるため、従来型のファイルシステムを下層に持たなくても、エディターで切り替えたり、モデルへ送信したり、プレビューで実行したり、ZIPにまとめたりできます。

インターフェースにはReact、構文強調にはPrism、ブラウザー内でのJSXコンパイルにはBabel、パッケージ作成にはJSZip、アシスタントの回答表示にはMarkedを使用しています。そのすべてが1つの`index.html`に収まっています。

## ホストがAPIになる

開発者が最初に理解すべき点は、SDKがクラウドクライアントではないことです。

```js
const layla = new LaylaSDK();
```

設定はこれだけです。キーもベースURLもありません。`LaylaSDK`は次の呼び出しをシリアライズします。

```js
window.ReactNativeWebView.postMessage(...);
```

Laylaがネイティブ側で処理を行い、イベントをWebViewへ返します。そこからミニアプリは、キャラクター、ストリーミング形式のチャット補完、画像生成、音声、プライベートファイル、ネイティブ共有にアクセスできます。

実際には、この仕組みによってミニアプリを小さく保てます。通常ならバックエンド、認証、メディアサービス、ストレージ層が必要な機能も、ホストがその4つをすでに備えているため、メソッド呼び出しだけで実現できます。

## 自分のキャラクターがアシスタントになる

CodeKittyは各キャラクターのポートレートを取得し、検索可能なギャラリーに表示して、その中からコーディング仲間を選べるようにします。Character Cardのデータから名前と性格を取得し、CodeKittyがシステムプロンプトに書き込みます。アシスタントはキャラクターらしい口調を保ちながら、バグの説明やファイルの修正を行えます。

キャラクターライブラリは、どのミニアプリからも読み取れるパーソナライズ層です。フィットネスアプリならキャラクターをコーチに、学習ツールなら科目別の家庭教師に、物語ゲームなら登場人物にできます。キャラクター一覧はすでに存在し、SDKを1回呼び出すだけで取得できます。

## モデルが提案し、アプリが適用する

変更を依頼したとき、CodeKittyは入力文をそのままモデルへ渡すわけではありません。コーディング仲間の性格、アクティブなファイル名とその全内容、期待する出力形式、プロジェクトのメモ、直近のチャット、ライブプレビューで取得したエラー、SDKドキュメントを含むコンテキストパッケージを組み立てます。そのうえで回答形式を制約します。

ソースファイルの場合、モデルはファイル全体の置換内容かJSONパッチを返す必要があります。

![検索項目と置換項目を含むJSONパッチを表示したコードエディター。](./json-patch.avif)

`app.json`の場合、モデルは文書全体を返します。画像アセットの場合は、コードではなく視覚的なプロンプトを提案します。

この分離が重要です。モデルは提案し、CodeKittyがそれを適用するか、どのように適用するかを判断します。モデルがストレージやネイティブホストへの書き込み権限を得ることはなく、適用した変更はすべて取り消し可能なスナップショットになります。言語モデルに状態へ影響を与えさせるなら、コードが直接実行するアクションではなく、コードが検証できる提案を出力させてください。

スマートフォン上のローカル推論には時間がかかるため、生成はストリーミングで行われます。

![Laylaのチャット内容、推論イベント、finalContent()を処理するJavaScriptストリームハンドラーを表示したコードエディター。](./streaming-events.avif)

推論は独立したチャンネルで届き、折りたたみ可能なパネルに表示されます。ストリームのハンドルは保持されるため、停止ボタンから中断できます。ミニアプリがオンデバイス生成に依存する場合、進捗も製品の一部として扱ってください。テキストをストリーミングし、画像生成の各段階を表示し、必ずキャンセルできるようにします。

## プレビューがブリッジを借りる

ライブプレビューは、CodeKittyの技術面で最も興味深い機能です。

`index.html`はサンドボックス化されたiframeで動作します。起動前にCodeKittyは2つのものを挿入します。1つ目は、ラップしたコンソールメソッドとエラーハンドラーです。これにより、捕捉されなかった例外がコンソールパネルに表示され、次の質問でモデルのコンテキストにも含まれます。「実行する、エラーを確認する、コーディング仲間に質問する、パッチを適用する、もう一度実行する」という短いループが生まれます。

2つ目は、`window.ReactNativeWebView`のプロキシです。iframe内のアプリがSDKを呼び出すと、プロキシがブリッジメッセージをCodeKittyへ中継します。CodeKittyはそれを実際のLaylaホストへ転送し、ネイティブの応答をiframeへ返します。

プレビューアプリはCodeKittyのLayla接続を借ります。ファイル操作にはプロジェクト単位のファイル名プレフィックスが付くため、テストアプリが`saveFile`を呼び出してCodeKitty自身のライブラリを上書きすることはできません。ミニアプリは別のWeb体験をホストしながら、その体験にどのネイティブ機能を渡すかを正確に制御できます。

## アイコン、背景、エクスポート

Laylaのパッケージにはアイコンと背景が必要なため、CodeKittyは画像ファイルをほかのファイルと同等のプロジェクトタブとして扱います。プロンプトを書くか、コーディング仲間に作成を頼み、端末上で画像を生成します。

```js
const imageSrc = await layla.images.generateImage();
```

結果はcanvasを使って中央で切り抜かれます。アイコンは256×256、背景は854×480です。エクスポートまではデータURIとして保存されます。

エクスポートすると、`app.json`、`index.html`、アセットをルートに含むZIPが作成されます。ビルドは2種類あります。

- **開発ビルド**では、すべてを読みやすく編集可能な状態に保ちます。
- **smashedビルド**では、JSXをコンパイルし、Reactをインライン化し、フォントをデータURIとして埋め込み、SDKバンドルをオフライン用に書き換え、ネットワークを必要としない自己完結型の`index.html`を1つ生成します。また、後からパッケージをCodeKittyへ再インポートできるよう、非表示のソースコピーも含めます。

エクスポートはチェックポイントであり、終点ではありません。

## 自分でミニアプリを作るときの要点

CodeKittyの優れた考え方を利用するために、IDEを作る必要はありません。

ホスト機能を1つ選び、単に機能を見せるのではなく、実際の作業手順を解決するために使ってください。CodeKittyが画像を生成するのは、パッケージにアイコンが必要だからです。ローカル生成を前提に設計し、ストリーミング、進捗表示、停止操作を用意します。モデルは、コードが検証できる契約の内側に置いてください。

大きなデータはブリッジに通さないでください。CodeKittyがライブラリを小さなインデックスとプロジェクトごとのペイロードファイルに分けているのは、大きなbase64ブロックがWebViewの境界を越えるとスマートフォンの動作が遅くなるためです。フィードバックループも作りましょう。プレビューコンソールがモデルのコンテキストになるからこそ、デバッグループが機能します。

そしてLayla内でテストしてください。SDKのmockを導入していないブラウザーでの挙動は、正式な基準にはなりません。

## よくある質問

### Laylaミニアプリとは何ですか？

Layla内で動作し、Layla SDKブリッジを介して端末上のAI（ローカルモデル、画像生成、音声、キャラクター、プライベートストレージ）を利用できる自己完結型のWebアプリです。`app.json`、`index.html`、アセットを含むZIPとして配布されます。

### 作成するにはコーディングの知識が必要ですか？

必要な知識は想像より少ないかもしれません。CodeKittyのアシスタントがコードを書いて修正し、利用者は自然な言葉で指示します。HTMLとJavaScriptを知っていれば作業が速くなり、モデルの間違いも修正できますが、「説明する、プレビューする、修正する」という流れは知識がなくても実行できます。

### CodeKittyはオフラインで動作しますか？

AIはオフラインで動作します。コーディングアシスタントにはローカルモデルが使われ、書いた内容がスマートフォンの外へ出ることはありません。現在、CodeKittyのインターフェースライブラリは初回起動時にCDNから読み込まれるため、起動には接続が必要です。smashedビルドでエクスポートしたアプリは完全に自己完結しており、ネットワーク接続なしで動作します。

### コードはどこに保存されますか？アップロードされますか？

外部には送られません。プロジェクトは端末上にあるLaylaのアプリ別プライベートファイルストレージに保存されます。モデル推論も端末上で実行されます。プロジェクトを保持するアカウント、同期機能、サーバーはありません。

### 作ったミニアプリを共有できますか？

はい。エクスポートすると、Laylaを使用している人なら誰でもインポートできるZIPが生成されます。必要であれば、LaylaのMini-app ManagerからLayla Cloudへアップロードできます。

### ミニアプリは何にアクセスできますか？

キャラクターとそのポートレート、ローカルモデルを使ったストリーミング形式のチャット補完、推論エンジンの選択、画像生成、インストール済みのTTS音声、そのアプリに限定されたプライベートファイルシステムにアクセスできます。ほかのアプリのファイルにはアクセスできません。

### SDKのリファレンスはありますか？

はい。[`@layla-network/sdk`のリポジトリ](https://github.com/l3utterfly/layla-sdk)を参照してください。

## 次のミニアプリを作る

CodeKittyは猫をテーマにしたコーディング仲間付きのIDEですが、それだけでは、より興味深い事実を十分に表していません。ミニアプリは、完全なローカルワークフローになれます。持ち運び可能なWebページでありながら、キャラクター、モデル、画像、音声、ファイル、プレビュー、共有を連携させられます。

CodeKittyは、このシステムをソフトウェア作成に使います。同じ仕組みで、インストール済みの音声を使って練習問題を読み上げる語学チューター、端末内に保存されて関連する過去の記録を提示する日記、自分のキャラクター一覧を配役に使うストーリー制作ツール、セッションの合間にメッセージを送るキャンペーンツールなども作れます。

入り口はSDK全体を学ぶことではありません。Layla内で行えばより良くなる場面を1つ見つけ、その場面を実現する最小限のものを作ってください。
